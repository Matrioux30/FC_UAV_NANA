# MPC Accelerator Test Vectors

Generated by `main_golden_model.exe` (run from `quadcopter_mpc/`). 4000 cycles: hover (0–999), step (1000–1999), trajectory (2000–3999). Ts = 5 ms.

## What the accelerator computes (per control cycle)

```
g  = MX * x - MR * r                          (20)    Prediction Engine (MAC)
repeat N_ITER = 80 times (z = y = 0 at start, cold start):
  rhs   = rho * (z - y) - g                   (20)
  u     = W * rhs                             (20)    Numerical Solver Kernel (MAC)
  u_hat = alpha * u + (1 - alpha) * z
  z     = clamp(u_hat + y, ZMIN, ZMAX)                Constraint Evaluation
  y     = (y + u_hat) - z
output z (20 values); the PS uses z[0..3]
```

Inside one iteration, `rhs` is computed from the previous `z`, `y` for all 20 elements first; then elements `i = 0..19` are updated.

PS side (not in PL): `x_q = X_SCALE .* x`, `r_q = R_SCALE .* r` (powers of two, so a shift), and `u_k = U_SCALE_k * z_k` with `F_total = u_0 + 0.66708 N`. The values are in `rom_*/formats.txt`.

## Number formats (signed 32-bit, two's complement)

| Signal | Q16.16 build | Q8.24 build |
|---|---|---|
| data: x, r, g, rhs, u, u_hat, z, y, ZMIN, ZMAX | Q16.16 | Q8.24 |
| W | see `rom_q16_16/formats.txt` | see `rom_q8_24/formats.txt` |
| MX, MR, rho / alpha / 1−alpha | (per-ROM format) | (per-ROM format) |

Arithmetic rules (must match bit-exactly):
- **add/sub**: exact, then saturate to int32.
- **coef × data** and **dot products**: multiply raw integers exactly and sum them in a wide accumulator (≥ 72 bits for Q16.16; 128 bits is safe). Then apply **one** rounding step: `(acc + 2^(F-1)) >> F` (arithmetic shift, F = fractional bits of the coefficient). Then saturate to int32.
- No intermediate overflow occurs on any of the 4000 vectors. The golden model counts every saturation and reports 0.

## Files

| File | Content |
|---|---|
| `rom_<fmt>/W.mem` | 20×20 row-major, one 8-digit hex word per line (`$readmemh`) |
| `rom_<fmt>/MX.mem` | 20×12 row-major |
| `rom_<fmt>/MR.mem` | 20×80 row-major; column `p*4 + c`, with c = x_ref, y_ref, z_ref, psi_ref |
| `rom_<fmt>/ZMIN.mem`, `ZMAX.mem` | 20 words, data format |
| `rom_<fmt>/PARAMS_rho_alpha_1malpha.mem` | rho, alpha, 1−alpha |
| `test_vectors_<fmt>.csv` | per cycle, raw int32 (decimal): inputs `x0..x11`, `r{p}_{x,y,z,w}` (already scaled), expected `g0..g19`, expected `z0..z19` |
| `test_vectors.csv` | the same cycles in floating point: state, reference horizon, `u_exact` (converged QP), `u_float` (80 iterations), `u_q16_*`, `u_q824_*`, `Constraint_Active` |

## Checking an implementation

`python scripts/verify_test_vectors.py q16_16 --all` is an independent integer-only model. It is built from the ROM and format files only. It currently reproduces 4000/4000 cycles bit-exactly for both formats. Use it as the reference when debugging RTL mismatches.
